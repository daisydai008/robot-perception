# Sim2real 通用标定流程

标定是 sim2real 的平台级前置条件，独立于抓取、剪切等具体任务。本流程建立相机、机器人与世界坐标之间可追溯的几何和时间关系；通过后，各任务引用同一标定版本，再完成物体、工具和接触相关的专属测量。物体 mesh、tag-to-link、铰链与材料参数不属于本流程的通用验收项。

流程：**准备与验收约定 → 内参复核 → RGB-D 几何 → 相机与机器人外参 → 时间对齐 → 独立验收与版本发布**。纯 RGB 平台跳过深度项；静态与动态使用范围分别签收。相机取流许可不包含机器人连接或运动，涉及机器人换位的采集需单独确认现场安全与操作许可。

## 1. 确认靶标、安装与验收条件

先辨认实物，再选择检测器：棋盘格记录方格数与内部角点数，圆点板记录排列和中心间距，ChArUco 记录格数、dictionary、IDs 布局及生成约定。型号不能代替这些参数；ChArUco 还需核对 OpenCV 的 legacy pattern。测量水平、垂直多个间距，记录实际尺度、板面平整度和量具不确定度，不直接采用订单尺寸。若使用 AprilTag，尺寸取黑色外框边长，不含白色静区。

固定相机与夹具，确认相机是否随头部或末端运动；记录设备序列号、分辨率、裁剪、曝光、驱动版本与安装照片。硬件取流与网络部署由消费者的 camera adapter / 本机配置负责，不由本包启动驱动；网络排障不属于几何标定。

正式采集前，负责人确定工作距离、视野覆盖、样本量、剔除规则、误差上限和独立参照。求解前固定 train/heldout 的姿态或场次，不按拟合结果挑选验证数据。

| 验收项 | 需预先明确的指标 |
| --- | --- |
| 图像与内参 | 检测成功率、留出角点误差、中央与边缘覆盖 |
| RGB-D 几何 | 独立长度/距离误差、配准偏差、深度有效率 |
| 外参及控制坐标系 | 留出几何位置/角度误差、静态重复性、参照不确定度 |
| 时间 | 帧配对差、图像—状态时间偏差与抖动、端到端延迟 |

**产出：**实测靶标配置、安装/profile 记录和采集验收协议。阈值由使用需求决定，不设未经批准的统一精度数字。

## 2. 复核相机内参

优先验证厂家内参，不因买到标定板就重新拟合。确认图像对应的 K、D 和畸变模型：raw 图像与 rectified 图像不能混用参数；RealSense 的不同 Brown 模型也不能仅凭系数个数互换。

保持相机固定，手动改变板的位置、距离及多轴倾角，覆盖画面中央、边缘和四角。避免反光、模糊、所有图像均正对板，或用同一静态视频的相邻帧充数。板平放在桌上的一张图只适合检查检测效果。

先用厂家模型检查留出图像与独立实测几何；不满足要求时，排除板型、尺度和成像问题后再拟合候选内参。K、D 仅用 train 求解，heldout 固定 K、D 后只估计板位姿，报告每幅图的残差和检测失败。**低 reprojection error 不证明米制尺度或绝对位姿准确。**

**产出：**适用于确定图像 profile 的内参及验证结果；候选模型不自动覆盖驱动参数。

## 3. 验证深度尺度与 RGB-D 配准

使用未参与拟合的已知距离、平面和几何边缘，覆盖实际工作距离与倾角，检查深度尺度、偏差、空洞和离群点。确认深度单位，不能只由 `16UC1` 推断为毫米；按预定规则统计有效深度与失败样本。

区分 native depth 和 aligned depth：前者使用自身光学坐标系及对应相机模型；映射到 RGB 时需使用经过核对的相机内部外参。已对齐到 color 的深度不能继续使用 native depth 内参。RGB 板拟合通过，不等于 depth 内参或两传感器外参已校准。

**产出：**深度单位、color↔depth 变换与配准验证，以及工作区内的深度误差和有效率。保存原始数值深度，不用 preview、伪彩色图或滤波后图像代替原始数据。

## 4. 标定相机、机器人与控制坐标系

统一使用右手系、米和弧度，明确 quaternion 顺序与变换方向。记 \({}^{A}T_B\) 为将 B 中坐标变换到 A；定义世界/任务基座 B、相机光学坐标 C，以及安装或末端坐标系。相机外壳原点不是光心，厂家机械变换只有在安装和完整光学链核验后才能使用。

按实际安装选择方法：固定相机求 \({}^{B}T_C\)；随头部或末端运动的相机先求安装外参 \({}^{H}T_C\)，再用已验证的 FK 与同步状态计算 \({}^{B}T_C(t)={}^{B}T_H(t){}^{H}T_C\)。单一姿态下测得的外参不能直接用于所有姿态；无可靠运动链时，只批准固定姿态使用。

若固定相机、板 Q 刚性装在机器人末端 E，可通过多姿态 eye-to-hand 联合求解：

\[
{}^{B}T_{E,i}\,{}^{E}T_Q = {}^{B}T_C\,{}^{C}T_{Q,i}.
\]

板安装变换与相机外参均可能未知，不能假设板就在末端原点。采集需覆盖多轴旋转和工作区平移，并使用经过核对的实测关节/FK；eye-in-hand 使用其对应安装关系，不能照搬输出方向。其他独立测量方法可替代手眼采集，但必须有可追溯参照。

同时核对 robot base、法兰、wrist、TCP/control frame 的定义、关节顺序、零位和单位。用未参与求解的姿态检查变换链和独立实测位置/方向，而不只看拟合残差。厂家机械尺寸只是候选参照，仍需在设备侧核验完整 optical 链，不能当作已通过的外参。

**产出：**方向与适用范围明确的坐标变换链、独立几何误差及重复性记录；软件 IK/FK 数值测试不能代替实装验收。

## 5. 建立时间关系并验证延迟

记录各图像、相机主机、机器人状态的 timestamp 来源、单位、epoch 和同步机制。软件 receipt time 不是曝光时间，SDK cache 的读取时刻也不是控制器采样时间；不同主机的 monotonic clock 不能直接相减。RGB/depth header 相同，不足以证明同时曝光。

用共同时间基准或双方可观察的事件估计偏移、漂移与抖动，再用留出序列验证。动态任务需连续记录图像和机器人状态，并测量图像可用、估计、排队、策略读取及控制响应的延迟。稀疏静态快照不支持这类验收；静态计量可采用有明确停稳记录的姿态，但结果不自动适用于动态使用。

**产出：**时间映射、配对/插值规则、最大观测年龄和延迟范围。阶段 4 的动态数据必须满足这些条件后才可签收。

## 6. 独立验收、版本与复测

使用未参与求解的视角、姿态或场次，并加入有测量不确定度的独立几何参照。分开报告拟合误差、留出误差、绝对几何误差与重复性；检测失败、失配和中断不能静默剔除。某项不满足预定要求，就限制相应使用范围或补采，不靠策略试验替代标定证据。

归档原始图像/深度、时间戳与机器人状态、测量和协议记录、相机/软件版本、求解输入与输出、失败明细和验收结论。负责人签收后，将 candidate 标为 approved，明确适用的设备、安装、profile、工作区和静态/动态范围。仿真和部署引用同一版本与坐标约定；标定通过不自动授权机器人执行任务。

每次正式场次前检查安装并复测已知几何。相机或夹具移位、TCP/头部定义改变、分辨率/裁剪或模型变化时，重标受影响项；曝光和固件等变化需复核成像及时间性能。保留上一通过版本，不用失败场次覆盖。

## 当前进度与工具边界

截至 2026-11-09，D435 已完成 Jetson 本地与 workstation 短时 RGB/native-depth 取流检查，稳定段约 30 Hz；收流记录保存在本仓库 `data/vision_calibration/`（只在本机，不随本包分发），workstation DDS profile 见 [config/](../config/README.md)。**物理内参、外参与时间精度尚未验收。** 板和 tags 已到位；标定板为 DFOPTIX `Q12-290-20` 普通棋盘，12×9 方格、11×8 内角点；用户已确认单格实测 20 mm，黑白格区域 240×180 mm、整板 290×230 mm。下一步是确定外部位姿参照与采集协议；量具和测量不确定度记录仍待补充。

现有 [标定 CLI](../src/robot_perception/calibration/calibrate.py)（`robot-calibrate`） 中，`intrinsics` 仅支持 ChArUco，`detect-tags` 仅输出检测角点；`capture` 要求 RGB、native depth、aligned depth 及逐帧匹配的 CameraInfo，alignment 关闭时不能直接使用。[固定相机外参 UI](extrinsics_ui.md)（`robot-extrinsics-ui`） 独立支持普通棋盘的 RGB-only 离线导入或显式订阅、已知板参照与 eye-to-hand 求解、train/heldout 验证和候选归档，不要求深度对齐。使用前仍需确认实测尺度、raw 模型、物理角点朝向及独立外部位姿；工具不控制机器人、不发布 TF、不改变驱动，候选输出不代替实装验收。

本轮已批准阶段 A 的本地迁移与离线接入；此 package 仅实现上述流程中的部分软件工具，不宣称完成深度、时间或物理精度验收。当前授权与后续范围见[任务契约](task_brief.md)。
