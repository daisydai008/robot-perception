# 头部 D435 相机标定

本文说明 Tianji 机器人头部 D435 的标定方法、验证结果和适用范围。2026-11-10 完成的外参结果见 [extrinsics_base_link_20261110.json](../../config/cameras/d435/extrinsics_base_link_20261110.json)，已由用户签收，适用范围为头部固定、静态使用。

## 坐标约定

`T_A_B` 表示把 B 坐标系中的点变换到 A 坐标系，长度单位为米。`base_link` 是厂商 URDF 的机器人基座；`Head depth_Link` 是 URDF 中代表 D435 外壳的 link；`d435_link` 是 Intel 约定的相机 link，原点在深度原点（左红外镜头），x 朝前、y 朝左、z 朝上；`d435_color_optical_frame` 是彩色光学坐标系，x 朝右、y 朝下、z 朝前。

## 图像与内参

彩色流使用 848×480@30 rgb8，水平视野约 70°；该分辨率在运行中通过 ROS 参数切换（方法见 [config/README.md](../../config/README.md)），Jetson 部署默认仍为 640×480。内参直接采用驱动发布的出厂值：fx 603.646、fy 603.362、cx 430.930、cy 245.467，plumb_bob 模型，畸变系数全为 0。

出厂内参经一次手持棋盘检查后采用。检查时用 `robot-extrinsics-ui` 实时订阅彩色流，手持 DFOPTIX Q12-290-20 普通棋盘（11×8 内角点，单格 20 mm）采集 19 幅，每幅都检出全部 88 个角点，再用出厂内参逐幅做 IPPE PnP。11 幅的重投影 RMS 为 0.16–0.30 px，棋盘位于画面中上部、距离 0.56–0.73 m；另 8 幅为 0.42–1.14 px，多在画面下半部或更近处（0.51–0.61 m），单个角点最大误差 3.0 px。角点覆盖横向 177–713 px（共 848 px）、纵向 18–457 px，画面左侧三分之一和四角没有覆盖。用其余各幅重新拟合畸变后，留出幅的平均 RMS 从 0.44 px 降到 0.29 px，说明出厂模型在这些区域有约 1 px 的系统偏差，0.6 m 处约合 1 mm；由于覆盖不足，这次拟合只作诊断。用户据此决定采用出厂内参。

## 外参：由厂商模型拼接

外参不做拟合，由三段已发布的几何拼接而成：

$$
{}^{B}T_{C} = {}^{B}T_{H}\;{}^{H}T_{L}\;{}^{L}T_{C}
$$

其中 B 为 `base_link`，H 为 `Head depth_Link`，L 为 `d435_link`，C 为 `d435_color_optical_frame`。

\({}^{B}T_{H}\) 取自厂商 URDF（`Marvin pro_V3.0_M6_696_SHW5G_TJgripper.urdf`，robot `Pro-m6-696`）的固定关节 `Head depth_Joint`：平移 (0, −0.10339, 1.24614) m，绕 x 轴转 65.0°。

\({}^{H}T_{L}\) 来自 Intel realsense-ros 4.58.4 的 D435 机械模型，因为 URDF 只给出外壳 link，没有光学坐标系。Intel 的 `_d435.urdf.xacro` 把 `d435_link` 放在深度原点：沿外壳长边距中心 17.5 mm、在前玻璃后 4.3 mm。把 Intel 外壳网格 `d435.dae` 配准到厂商网格 `Head depth_Link.STL`，两者形状一致，表面距离中位数 0.4–0.6 mm，前表面是 H 的 y = 0 面（外法线朝 −y）。由此 `d435_link` 原点在 H 中位于 (17.5, 4.3, 0) mm，坐标轴为 x_L = −y_H、y_L = x_H、z_L = z_H。

\({}^{L}T_{C}\) 取驱动在 `/tf_static` 中发布的出厂标定：彩色镜头位于深度原点 +y 方向 15.04 mm 处（z 方向另有 0.4 mm），两者相对旋转 0.63°。

拼接结果：彩色光心位于 `base_link` 的 (0.0325, −0.1019, 1.2502) m，光轴偏离竖直向下 25.3°，并朝 −y 方向倾斜。结果文件给出 `base_link` ← `d435_color_optical_frame` 与 `base_link` ← `d435_link` 两项的矩阵和四元数，以及上述三段的精确数值，可以独立重算。

## 验证

分两步。先用 URDF 正运动学与天机运动学库对照：两条臂各算 151 组随机关节角，拟合固定偏移后最大残差 0.0055 mm / 0.0016°，确认 URDF 的关节约定可用。再用机械臂叠图和原生深度核对外参：静止姿态下读取关节角并采集彩色和原生深度，把 Link1–Link7 投影到画面，计算深度点到模型表面的距离。

两个静态姿态下，深度点到模型表面距离的中位数 / p95 为：home 位左臂 2.5 / 10.1 mm、右臂 5.1 / 8.4 mm；第二姿态左臂 3.5 / 9.2 mm、右臂 4.2 / 7.8 mm。由深度求出的相机修正量为 4.33 mm / 0.58° 和 5.11 mm / 0.53°；用一条臂求出的修正放到另一条臂上都会变差，所以不采用修正，直接使用拼接结果。用户目视确认两次叠图均对齐后签收。第二次记录保存在本机 `data/vision_calibration/extrinsics_recheck_20261110_2102/`，不入 git。

## 适用范围与限制

仅适用于头部固定、原装支架不变的静态使用；848×480 与 640×480 共用同一位姿，内参只差 cx（640×480 时减 104 px）。只验证了两个静态姿态，且两条臂都在画面边缘，画面中部未覆盖；没有独立计量参照，与手臂模型的一致性为几毫米量级。深度单位按 0.001 m 取用，图像与机器人状态的时间同步未验证。头部、支架、相机、URDF 或驱动变化后需重新复核。

## 复核

前提：Jetson 上 D435 在运行，workstation 能收到 `/cameras/d435/*`，彩色流已切到 848×480。部署 DDS 设置已于 2026-11-11 修复为不按 IP 选网卡（修复在 GitLab `dev` 的 `0c5a648`）；部署前确认执行部署的电脑已包含该提交。

1. 拍摄前后各读一次关节角（只读，需现场许可）。
2. `robot-calibrate rgbd-snapshot` 采集彩色和原生深度。
3. `robot-calibrate arm-check` 生成叠图、深度残差和修正量估计，由人目视判断是否对齐。

两条命令的完整参数和输出说明见[机械臂叠图检查](arm_overlay_check.md)。
